Serial vs parallel — impact for large images

We compare this parallel MPI run (wall time = slowest rank) to estimated serial time from four pre-recorded runs of the serial pipeline on similar workloads (same algorithm family: load, grayscale, Gaussian blur, Sobel, threshold, saves). The estimate is a linear fit: time ≈ a × pixels + b on those benchmarks — useful for reasoning about throughput before sending pixels to an LLM.

Reference serial runs (ground truth for the fit)

Serial data lives under serial/serial_image_processor/<stem>/metrics.csv. Parallel time uses max(total_s) across ranks for this run. Different CPUs change absolute seconds; the ratio and trend still illustrate why parallel preprocessing scales better for multi-megapixel frames.
